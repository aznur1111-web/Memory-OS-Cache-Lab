Visual Lab — Memory & OS caching

Change one engineering variable and observe the model. Values are simulated, not measurements from this computer. The dark stage remains consistent across application themes.

01 / Cache budget vs useful hits

Estimate how much of a working set fits in a reusable RAM cache. This is a capacity illustration, not a kernel policy predictor.

Reuse model: min(cache budget ÷ working set, 1) × repeated-use share. One-pass scans reduce reuse; hot-subset mode assumes 25% of data accounts for most requests.

02 / Average read service time

Compare a page-cache hit path against a miss that reaches backing storage.

MODEL / WEIGHTED MEAN15.70 µs
HitMeanMiss
Mean = hit probability × hit-path time + miss probability × (software overhead + storage time). Values are illustrative; real results depend on request size, queues, filesystem, concurrency and device.

Step through a typical conceptual path. A cache hit skips a new storage read; a miss may trigger block I/O. Real path details vary by OS, filesystem and API.

These are deterministic teaching models. They do not inspect or change real system memory, evict actual pages, flush files, or benchmark your storage. Assumptions are labeled throughout.
